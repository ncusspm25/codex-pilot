# Design principles

Codex should begin authorized work with the configuration already selected. Model and effort are computation choices; approvals for consequential actions are authority decisions. Avoid interrupting for the former while preserving the latter.

Rigor should match the work. A typo needs a small check; a shared behavior change deserves focused tests; a high-impact or irreversible action needs stronger evidence and the required authorization.

Long tasks need continuity, not ceremony. Keep a compact view of the goal, constraints, decisions, unresolved issues, and current artifacts. Update it as facts change. Do not require repeated plans, recaps, or approvals between ordinary phases.

Use bounded context and make the smallest coherent change. Read what can affect the decision, preserve local interfaces and conventions, and expand the investigation when evidence points to a wider boundary.

Report what happened with evidence. An instruction file can guide behavior, but it cannot grant permissions or guarantee an outcome.
